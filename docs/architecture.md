# 维护指南与模块边界

## 从哪里开始读

后端入口是 `backend/app/main.py`,前端入口是 `frontend/src/main.tsx`。先沿一个具体操作阅读,不必从生成提示词开始:

| 要理解的操作 | 后端入口与主要逻辑 | 前端入口 |
| --- | --- | --- |
| 新建书籍并生成 | `api/generate.py` → `tasks/admission.py` → `tasks/novel_generation.py` | `pages/BookList.tsx` |
| Agent 自主创作 | `tasks/agent_generation.py` → `agents/runner.py`、`tools.py` | `pages/AgentChat.tsx`、`hooks/useAgentTrace.ts` |
| 保存章节正文 | `api/chapters.py` → 章节/正文与记忆任务同事务保存 | `components/ChapterEditor.tsx` |
| 修复创作记忆 | `api/memory.py` → `memory/sync.py` | `components/MemoryPanel.tsx` |
| 整理目录 | `api/chapters.py`、`api/volumes.py` | `components/CatalogTree.tsx`、`utils/catalogReorder.ts` |
| 查看人物/剧情进展 | `memory/facts.py` → 人物/剧情读取接口 | `CharacterFacts.tsx`、`PlotThreadPanel.tsx` |

## 后端职责

`api/` 负责 HTTP 参数、资源存在性与响应契约。路由不持有长时间运行的任务。`tasks/admission.py` 在真正启动前统一检查模型能力、容量和同书互斥,把书籍与任务一起提交;任务提交成功后才启动执行。

`tasks/` 负责任务状态、暂停/恢复、检查点、同书互斥和进程退出时的取消。`agents/` 负责生成业务:流水线决定下一阶段,工具把 Agent 决策转换成受校验的操作。结构化模型输出在 `agents/stages.py` 校验,验证通过后内容和阶段检查点一起提交。模型输出不能直接作为“阶段已完成”的证据。

书籍规划快照与结果校验在 `agents/book_plans.py`，固定流程和 Agent 共用同一提交边界。章节计划的插入、排序和重规划在 `agents/chapter_plans.py`;正文落库快照保护在 `agents/chapter_writes.py`。等待模型期间不持有写事务,提交结果前在短写事务中核实章节未被其他编辑改变。冲突会保留用户的新正文、章纲与归属,旧生成结果不会覆盖它们。

工具契约、注册和分派集中在 `agents/tool_registry.py`，小说工具实现在 `agents/tools.py` 注册；Runner 依赖契约，不导入小说流水线。只有纯状态查询不占写操作预算；评审会写重写许可，计入预算。

Agent 的评审重写先检查次数，再核对被评审正文的版本并发放单次许可。作者改正文会撤销许可，开始重写在短写事务内消费许可，每次 Agent 新运行清除历史许可。已完成正文的重写失败、取消或为空时保留原完成状态。

Agent 状态由 `agents/state.py` 汇总。完成数量通过共享 SQL 规则核对实际非空正文，成书校验和续写队列只读取计数或待写 ID，不把全书正文载入 Python。章节明细限制为 32 条并优先展示未完成章；卷统计和末章 ID 始终保留，未归卷章节也能定位。`get_book_state` 的 `chapter_offset` 用于继续读取当前窗口，写入后应重新从默认窗口读取，避免沿用已经移动的偏移。

`llm/` 只处理供应商协议、有限超时、输出上限和实际调用预算,不访问书籍数据库。供应商请求与业务重试分开,评估工具可以明确禁用额外重试。流式正文必须收到供应商的正常完成信号；断流、明确截断或供应商错误不会成为成功结果。嵌入结果在适配层校验为非空、有限且可存储的 float32 数值向量。`agents/errors.py` 区分可以展示的业务错误和包含上游地址/凭据风险的异常,避免各调用点自己拼接异常原文。

`memory/` 分为四种职责:

- `sources.py`:读取来源、计算正文/设定版本、确定当前有效的记忆来源。
- `sync.py`:持久化同步任务、执行摘要/嵌入/事实提取、失败重试与状态审计。
- `context.py`:读取当前章节允许使用的历史并组装上下文;不因一次查询重新入队或提交设定。
- `facts.py`、`vector_store.py`:分别负责有证据的正文事实回放和本地数值向量存储。向量命中还需通过 SQL 的归属、版本与时间位置检查。调用方使用明确的 `VectorHit`、来源类型和历史 ID 参数，Chroma 过滤表达式只存在于存储适配器。

目录只投影卷/章的展示字段，在短读事务内构造一致快照；相同序号按 ID 排序，分页、Agent 与自动末章判断使用相同稳定顺序。目录拖拽在短写事务中批量读取并先校验整批归属，再更新排序和卷记忆任务。排序输入限制在浏览器可精确表示的整数范围内，空正文不能通过元数据 PATCH 标记为完成。

导出在一次显式读取事务中按 32 章分批读取正文并写到临时文件，读取结束才发送下载，避免长下载占用数据库或混入期间的修改。TXT 和 EPUB 共用该快照边界，成功、构建失败或发送中断都会清理文件；EPUB 仅在导出副本替换 XML 不允许的控制字符。

只有 Alembic 迁移负责生产表结构。`database.py` 为 SQLite 连接启用外键,应用启动不使用 `create_all()` 补齐缺失迁移。测试可以在专用内存库建最新结构;旧库迁移测试必须构造真实旧表。在线 Alembic 命令和服务共用 SQLite 文件锁，迁移内容与外键检查通过后一次提交，任何失败回滚结构和版本号。

## 保存成功与记忆可用是两件事

正文是权威数据,摘要、事实与向量是可重建的派生数据。修改正文时先在同一 SQL 事务中保存正文并登记记忆任务,再由后台处理派生数据。模型或向量失败不会撤销已保存正文。

每次同步绑定来源版本。旧请求即使晚到,也不能把旧摘要或事实标为当前可用。查询时再次核对版本,因此刚编辑正文、尚未完成重建的窗口内也不会召回过期内容。

章节事实记录既有角色/剧情线程的状态变化,每项都要有本章原文证据。提取、回放与完整审计共用结构、名单和证据校验，损坏批次会标记缺失并允许单章修复，轻量进度不读取事实正文。查询按当前 SQL 章序重放有效历史事实,不会把全书最后的人物状态带回早期章节。作者填写的 `Character.state_json`、人物卡和 `PlotThread.status` 保留原值;API 的 `derived_state`、`derived_status` 是正文推导结果。

章节事实分别核对正文和提取时的人物、剧情线程名单。名单变化或旧记录缺少名单版本时，记忆面板会显示缺失，作者可按需修复。名单编辑本身不会启动全书事实重建。

卷大纲 `Volume.summary` 是计划,`Volume.memory_summary` 是从已完成正文形成的事实摘要,两者不可混用。移动或重排章节只改变回放顺序和卷摘要来源,无须重新为相同正文提取全部事实或向量。

记忆面板首次进入、手动刷新及同步结束时进行完整审计。同步过程中只轮询 SQL 队列进度,避免每隔几秒遍历整部长篇正文及向量库。进度计数不能替代完整审计得到的可用记忆数量。 修复提交只做一次完整审计，按观察到的队列版本与状态入队后返回轻量进度；并发旧请求不能覆盖正在运行或刚完成的新任务。前端等待队列归零后再审计。

本地向量按书籍和嵌入服务版本存入独立集合。服务版本由供应商、规范化请求地址和嵌入模型计算，只保存摘要值。切换后，记忆面板将当前索引缺少的向量列为待修复，手动修复复用有效的章节摘要。旧集合保留在本地，删书时一并清理。

## 前端状态由谁负责

`api/` 统一 REST、会话及 SSE 协议,组件不拼后端路径。页面负责路由和面板组合,`components/` 负责展示与交互。状态文案放在 `constants/`,纯目录排序放在 `utils/`。

| Hook | 负责 | 不负责 |
| --- | --- | --- |
| `useGenerationStream` | 同步防重入、取消、唯一终态、卸载与旧回调隔离 | 正文草稿、日志展示、业务刷新 |
| `useMarkdownCardPanel` | 人物/设定列表与当前草稿、保存失败恢复 | Markdown 编辑器渲染 |
| `useTaskPanelData` | 当前书的任务/目录读取、活动任务轮询 | 启动生成或修改正文 |
| `useAgentTrace` | 轨迹分页、增量请求、切换任务时丢弃旧结果 | 页面路由与滚动布局 |
| `useBook` | 书籍元信息读取、重试、按需刷新 | 等待任务状态轮询完成 |
| `usePendingAction` | 表单提交期间的同步互斥 | 请求成功后的业务决策 |

正文 GET/PUT 返回精确文本的 `version`。编辑器保存和生成都携带读取时的 `expected_version`，后端在短写事务内核对；过期保存返回 409，过期生成发送明确的冲突事件且不调用模型，两者都不改变正文或记忆任务。旧客户端省略版本仍兼容，但不提供并发覆盖保护。冲突时保留草稿，明确确认后才重新加载服务器内容。

章节编辑器把服务器确认的元信息与用户正在输入的草稿分开。保存响应只合并状态和字数,不能整条覆盖本地标题、大纲和正文。切换书籍/章节使用明确的组件身份,旧请求和旧 SSE 不能写入新编辑会话。未保存的章节正文和原版本由 `store.ts` 按书/章保存在当前窗口内存中；跨面板、章节和路由恢复时重读服务器版本，冲突仍保留正文草稿。标题和章纲不属于该正文缓存。关闭或刷新窗口前提示，显式退出和成功删除对应书/章后清理草稿；删除失败保留。

认证失效时保留挂载草稿但隐藏工作区，受控表单、下拉菜单、气泡确认等通过同一工作区容器挂载并一并隐藏，同时销毁待确认的命令式确认框。重新登录会推进会话版本，触发书籍、目录和任务重读；已关闭的旧确认不重放。

卡片保存按字段互斥：名称失焦请求和正文保存可以并行，同字段请求及删除仍受保护。写入成功即释放操作锁并更新本地列表，后台列表刷新保留错误提示与请求顺序保护，慢读取不阻止下一次修改。

只有已知活动任务才持续轮询;窗口重新获得焦点时会刷新,以发现另一窗口启动的任务。Agent 的书籍请求与任务状态请求独立,慢书籍请求不会阻止显示任务终态和最后一页轨迹。

## 约束与验证

当前部署是一个共享账号、一个后端进程、一个 SQLite 和本地 Chroma。登录者可以访问工作台全部书稿。操作系统文件锁保证共享任一存储的第二个后端实例拒绝启动;这不是分布式任务租约。

后续若改多用户或多实例,需要同时调整资源归属、任务认领、存储和调用预算;只增加 worker 数不构成扩容方案。Chroma 的安全使用边界见 [依赖安全说明](dependency-security.md)。

日常验证命令和环境版本见 [开发验证](testing.md)。新增行为优先测试用户可观察的结果和事务边界:慢响应、取消、旧请求晚到、失败后重试、回滚和旧库升级。测试不读取真实 `.env`,不使用实际书稿数据库,不消耗真实模型额度。

尚未验收的问题仅保存在 [待优化清单](optimization-backlog.md);完成一项并通过回归后删除对应条目,历史原因和改动保留在 Git 中。
